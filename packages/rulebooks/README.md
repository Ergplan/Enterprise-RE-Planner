# Rulebooks

Regulation as versioned data. The engines (`apps/api/ergplan/engine`, `settlement`, `optimizer`) read only approved rule rows; an analyst approves; the LLM only drafts.

## Families (`schemas/`)

| Family | One row is | Used by |
| --- | --- | --- |
| `tod_slots` | A DISCOM's ToD slot definitions and surcharges/rebates | tariff evaluation, settlement, optimizer |
| `tariff_schedule` | Retail rates for one category and voltage | bill replay, avoided cost |
| `oa_charge` | One landed-cost charge component with its exemptions | landed cost |
| `settlement` | How injection is netted, banked, lapsed and set off | settlement simulator, optimizer |
| `regulatory_limit` | A cap or mandate | optimizer |
| `ists_waiver` | CERC ISTS waiver bands by commissioning date | landed cost (ISTS sources) |
| `net_metering` | Rooftop regime by size | landed cost (rooftop) |

Every row is `{scope, body, source_ref, position}`. `scope` (`scope.schema.json`) says when the row applies; `body` is validated by the family schema; `source_ref` (`source_ref.schema.json`) must point at a stored PDF page for `regulation`/`order` kinds.

## Conventions

- Money, rates and percentages are decimal **strings** (`"1.85"`), never JSON numbers — the engine parses them as `Decimal`.
- Units are those the regulation uses; `apps/api/ergplan/core/units.py` converts.
- Voltage-tabulated values use `value_by_voltage` keyed by kV as a string.
- A schema change is a decision: dated entry in `docs/decisions.md`, bump the `$id` only if rows become incompatible, and migrate exported YAML.

## Files

- `schemas/` — the JSON Schemas (reference data, committed).
- `states/<state>/<family>/<version>.yaml` — exported approved rulebooks, regenerated by the API; CI fails on drift.
- `golden/<state>/*.yaml` — golden test cases and, until Stage 1 seeds real rows, illustrative examples (clearly marked, status `draft`).
- Dates in YAML are quoted ISO strings (`"2026-04-01"`) so YAML does not turn them into date objects before schema validation.
