# billx 0.2: verified against the team's own bills

27 Oct 2026. Release 0.1 was built and tested on synthetic bills. 0.2 is the same engine and
the same contracts, corrected against **48 real bills the team confirmed** in the studio
(PVVNL, HPSEBL, MSEDCL, DHBVN and others, digital PDFs, scans and phone photos), with
open-access bills read and checked end to end.

## What changed since 0.1

**Verification (proof rule 2).** The text layer and local OCR find a field by the same label
rule, so on real layouts they agreed on the same wrong text (a neighbouring label taken as
the value). They no longer verify each other: a value is verified only when a local reader
and a model agree, or two model families agree. Every bill now needs at least one model
reading to pass. A refused bill still carries every field as read and every check run on it.

**Reading.** Each model is told what every field means (`description` in
`config/guaranteed_fields.yaml`; prompts `read_bill_v4`, `read_fields_v4`). Model B reads
every field still unverified after Model A; Model A's reading feeds the arithmetic while a
field is unverified; summary and details tables are kept apart (`detail_of`). The label rule
rejects headings and mostly-letter identifiers. Maximum demand is the recorded demand after
the multiplying factor.

**Open access (the team's definition, 26 Oct 2026).** On an open-access bill:

| Field | What it is | Example column (PVVNL adjustment bill) |
| --- | --- | --- |
| `energy.kvah` / `energy.kwh` | total consumption, before any set-off | 'MONTHLY CONSUMPTION' for the consumption month |
| `open_access.re_kwh` (and `non_re`, `banked`) | open-access units set off | 'Final Adjustable Units' |
| `energy.billed_units` (new, contract 1.1, optional) | units supplied by the grid, billed by the discom | 'BILLABLE CONSUMPTION AT DISTRIBUTION LICENSEE' |

Figures are stored **as printed, never converted**; each value's `unit` says kVAh or kWh
(profile key `printed_units`). New check **G22**: total consumption - open-access units =
grid units, within 1 unit, comparing like units only. On a bill without open access,
total consumption is the billed energy, as before.

**Checks.** G21 (detail lines add up to the line they itemise, "(-)" lines subtracted), G22
(above); G05 skips placeholder zero rates; G20 allows negative arrears and adjustments.

**Operations.** A model account with no credit fails at once instead of retrying for three
minutes. The studio re-reads a bill when the engine, a prompt, a profile or a key changes,
and has a "Re-read with the engine" link. Contract examples for a passed bill replay a
correct model reading of the synthetic file (`"models": "replay"`); none calls a real model.

## Measured on the team's bills

The 18 bills of the team's third folder (23 Oct) were read by this release's engine before the
team confirmed them, so their pre-fills measure it (counts only; no values here):

| | Count |
| --- | --- |
| Printed values the team confirmed | 363 |
| Engine's value equal to the confirmed value | 349 (96%) |
| Engine's value different | 8 |
| Engine found no value | 6 |
| Values the engine marked **verified** | 340 |
| of which equal to the confirmed value | 335 |
| of which different | 5: three `totals.net_payable` on open-access bills (a definition, see Open), two `demand.max_kva` the team marked "not printed" where the bill prints 'Actual MD (KVA)' |

The other 30 confirmed bills were pre-filled by earlier engines; measuring this release on
all 48 means reading them again with both models (`billx eval --golden --allow-cloud-model`,
about $0.39 a bill at placeholder prices, so about $19).

## Open

- **Net payable on open-access bills.** On PVVNL monthly bills the team confirmed 'Payable
  Amount' (before the due-date rebate); on PVVNL open-access adjustment bills, 'Amount
  Payable before Due Date (Rebate@1%)' (after it). The engine follows the first. Which one
  is the net payable decides the fix.
- Earlier MSEDCL open-access confirmations may hold the grid units in `energy.kvah`; under
  the definition above it is the total consumption.
- `audit_status` is `not_audited` on every bill, as in 0.1 (the tariff engine is later).
- The image for 0.2 is built by CI from the tag once GitLab runners are enabled (pending item
  9); 0.1's image notes and limits are unchanged.
