## What is unmeasured, and must stay labelled so

No real bill has been confirmed, so no accuracy figure exists. Every value the engine returns
carries its `proof` and `readers` (contract 1.1), every bill its `profile.status` (`draft` or
`none` today) and `audit_status: not_audited`.

The survey of the team's 65 unconfirmed files (`docs/accuracy/2026-10-14-unconfirmed-survey.md`,
run without keys): no file crashed; the discom was identified on 47; every file ended
`model_not_allowed`, because without a model no real layout had all its required fields
read by two independent local readers. The generic label rule did find the account number,
bill month and net payable on several digital layouts (APCPDCL, PSPCL, MSEDCL, TANGEDCO) and
never the reading period. With the keys in place, Model A reads every field and the local
readers confirm what they can; with ten confirmed bills per discom, the discom's own labels
make digital PDFs verifiable with no model at all. Details: `docs/stage-reports/stage-3.md`.

## What the team does next, in order

1. **Keys.** Open `~/billx/.env` in a text editor and fill the two lines
   `BILLX_OPENAI_API_KEY=` and `BILLX_ANTHROPIC_API_KEY=` (nothing after `=` but the key).
   Save. Nothing else changes; scans and photos become verifiable at once. Then run
   `cd ~/billx && tools/mac/doctor.sh` and check the two model-id lines say `pass`.
2. **Confirm ten AVVNL and ten PVVNL bills** in the studio: the numbered steps are in
   `docs/runbook.md` under "Confirm the sample set". About an hour per discom.
3. Run `cd ~/billx && .venv/bin/billx eval --golden --report docs/accuracy/$(date +%F)-golden.md`
   and read the report: the first real numbers (unmeasured), per field.
4. **GitLab:** in the project's settings enable shared runners and add the masked CI variable
   `CLIENT_IDENTIFIERS` (the lines of `~/billx-data/client-identifiers.txt`). CI then runs on
   every push and builds both images into the project registry.
5. **esgOS:** ask for `ESGOS_REGISTRY` (the image path) and `ESGOS_REGISTRY_KEY` (the
   service-account JSON) and add them as protected, masked CI variables; a push of the tag
   `0.1` (already on `main`) then copies the image to esgOS's registry. Tell esgOS's build
   agent to consume `accepted` (contract 1.1, `docs/contract-1.1.md`).
6. **Tariff orders:** the RERC order for AVVNL and the UPERC order for PVVNL covering the
   sample months, so the draft versions' `params` can cite them (today they carry the
   synthetic layouts' rates, marked as such).
7. Then say which deferred piece comes first (build prompt 5.0 section 14): anchors and the
   quality gate (4.2 Stage 4), hosting (Stage 3 of 4.2), or the tariff engine (5b).

## How to run things

`docs/runbook.md`. The service: `BILLX_TOKEN=<secret> billx serve` or `docker compose -f
docker/compose.yaml up` with a `.env` beside it. The build Mac's quirks (the Docker Desktop
proxy for builds, OCR cache and threads) are in `docs/decisions.md` and the runbook.
